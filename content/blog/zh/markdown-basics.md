## 什么是 Markdown？

Markdown 是一种轻量级标记语言，由 John Gruber 于 2004 年创建，Aaron Swartz 也作出了重要贡献。它最初的目标简单而远大：让人们用一种易读、易写的纯文本格式写作，并且可以按需转换成结构规范的 HTML。

HTML 需要成对的开始和结束标签，读起来十分杂乱；Markdown 则用直观的标点符号来表示格式。井号变成标题，星号表示粗体或斜体，短横线组成列表。即使还没转换，文档本身看起来也干净易读。

如今，Markdown 已成为网络写作的事实标准。GitHub 的 README、Reddit 的帖子、无数软件项目的文档都在用它，Notion、Obsidian、Slack 等工具也都支持它。对开发者、技术写作者以及任何在网上发布内容的人来说，掌握 Markdown 已不再是可选项。

## Markdown 简史

Markdown 诞生于人们对 HTML 冗长写法的不满。运营知名博客 Daring Fireball 的 John Gruber 想要一种像纯文本一样好读、又能生成干净 HTML 的写作格式。他和 Aaron Swartz 一起制定了最初的规范，并编写了负责转换的 Perl 脚本。

2004 年以来，出现了多种扩展和变体。GitHub Flavored Markdown（GFM）加入了任务列表、表格和删除线等功能；CommonMark 试图制定一份标准化规范，消除原始语法中的歧义；MultiMarkdown 则扩展了脚注、元数据等功能。

尽管存在这些差异，核心语法在各种实现之间依然非常稳定、一致。

## 基础语法

### 标题

Markdown 用井号（`#`）表示标题，井号的数量代表标题级别：

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

一个 `#` 是最大的标题（相当于 HTML 的 `<h1>`），六个 `#` 是最小的标题（`<h6>`）。大多数文档只用到一到三级标题。最佳做法是每篇文档只用一个 `# 一级标题` 作为主标题。

### 粗体与斜体

在 Markdown 中强调文字非常简单。用单个星号或下划线包裹文字表示斜体，用两个星号或下划线包裹表示粗体：

```markdown
*斜体文字* 或 _斜体文字_
**粗体文字** 或 __粗体文字__
***粗斜体*** 或 ___粗斜体___
```

大多数写作规范建议统一使用星号而不是下划线，因为下划线有时会和含下划线的文件名或 URL 冲突。

### 列表

Markdown 支持有序列表和无序列表。无序列表使用短横线、星号或加号：

```markdown
- 第一项
- 第二项
  - 嵌套项
  - 另一个嵌套项
- 第三项
```

有序列表使用数字加英文句点：

```markdown
1. 第一步
2. 第二步
3. 第三步
   1. 子步骤
   2. 另一个子步骤
```

有个有趣的细节：有序列表中实际写的数字并不重要，Markdown 总会按顺序渲染。不过从 `1.` 开始依次编号，原始文本会更易读。

### 链接与图片

链接用方括号写文字，用圆括号写 URL：

```markdown
[访问 OpenAI](https://openai.com)
[带标题的链接](https://example.com "示例网站")
```

图片的写法相同，只是前面多一个感叹号：

```markdown
![图片的替代文字](https://example.com/photo.jpg)
![标志](./images/logo.png "公司标志")
```

如果同一个 URL 要用很多次，可以使用引用式链接，让正文保持整洁：

```markdown
[Google][1] 是一个搜索引擎，[Bing][2] 也是。

[1]: https://google.com
[2]: https://bing.com
```

### 代码

行内代码使用单个反引号：

```markdown
用 `console.log()` 函数来调试。
```

代码块使用三个反引号（围栏代码块），还可以加上语言标识来启用语法高亮：

````markdown
```javascript
function greet(name) {
  return `Hello, ${name}!`;
}
```
````

支持的语言通常包括 `javascript`、`python`、`html`、`css`、`bash`、`json`、`typescript` 等，具体取决于渲染器。

### 引用

引用使用大于号：

```markdown
> 这是一段引用。
> 它可以跨越多行。
>
> 也可以包含多个段落。
```

引用可以嵌套：

```markdown
> 第一层
>> 第二层
>>> 第三层
```

### 表格

表格用竖线和短横线划分行与列：

```markdown
| 特性     | Markdown | HTML |
|----------|----------|------|
| 可读性   | 高       | 低   |
| 学习难度 | 简单     | 中等 |
| 可移植性 | 极佳     | 良好 |
```

可以在分隔行中用冒号控制列的对齐方式：

```markdown
| 左对齐 | 居中对齐 | 右对齐 |
|:-------|:--------:|-------:|
| 文字   | 文字     | 文字   |
```

### 分隔线

在一行中写三个或以上的短横线、星号或下划线，就能生成一条分隔线：

```markdown
---
***
___
```

它们适合用来在视觉上分隔文档中的不同部分。

## 进阶功能

### 任务列表

GitHub Flavored Markdown 支持任务列表，非常适合跟踪待办事项：

```markdown
- [x] 写引言
- [x] 添加代码示例
- [ ] 校对文章
- [ ] 发布
```

### 脚注

部分 Markdown 处理器支持脚注：

```markdown
这里有一句需要注明出处的话。[^1]

[^1]: 这是脚注的内容。
```

### 删除线

两个波浪号可以生成删除线：

```markdown
~~这段文字被划掉了。~~
```

### 定义列表

部分扩展 Markdown 实现支持定义列表：

```markdown
术语
: 术语的定义。

另一个术语
: 它的定义。
```

## 为什么要用 Markdown？

### 可移植性

Markdown 文件就是纯文本，在任何操作系统的任何文本编辑器中都能打开。不会被专有格式绑定，没有兼容性问题，也不需要特殊软件。

### 适合版本控制

由于 Markdown 是纯文本，它和 Git 等版本控制系统配合得非常好。你可以跟踪修改、查看差异，并通过拉取请求（Pull Request）协作——而这些在 `.docx`、`.pptx` 这类二进制格式上几乎无法做到。

### 速度快

用 Markdown 写作很快。熟悉语法之后，双手无需离开键盘，也不用伸手拿鼠标去点格式按钮。正因如此，Markdown 特别受注重效率的开发者和技术写作者欢迎。

### 灵活

一个 Markdown 文件可以转换成 HTML、PDF、EPUB、DOCX、演示幻灯片等多种格式。借助 Pandoc、printmd 以及各种静态网站生成器，这些转换都能顺畅完成。一次编写，处处发布。

### 专注内容

Markdown 去掉了排版上的干扰。用 Markdown 写作时，你关注的是文字和结构，而不是字号、颜色或页边距。内容与呈现分离，写出来的东西也会更清晰。

## 开始上手

学习 Markdown 最好的方法就是马上用起来。新建一个扩展名为 `.md` 的文件，用任意文本编辑器打开，开始写作。再配合一个预览工具，边写边看渲染效果。

如果想把 Markdown 转换成排版专业的 PDF，[printmd](https://printmd.app) 这样的工具能让事情变得很简单。你只管用 Markdown 写内容，排版和版式交给工具处理。

想快速练手的话，不妨用 Markdown 写下一份笔记、一个项目 README，甚至一篇博客文章。用不了一个小时，你就会觉得语法十分自然，并开始疑惑自己以前为什么要用别的工具。

## 总结

Markdown 已经成为现代网络最重要的写作工具之一。它简单、可移植、灵活，从随手笔记到完整的技术文档都能胜任。无论你是在为 API 写文档的开发者、记课堂笔记的学生，还是起草博客文章的写作者，Markdown 都能为你的工作打下干净、高效的基础。

本指南介绍的语法足以满足绝大多数写作需求。等你更熟练之后，可以进一步探索脚注、定义列表和数学公式等扩展功能，解锁更多可能。
