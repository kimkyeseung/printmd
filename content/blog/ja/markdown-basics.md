## Markdown とは？

Markdown は、2004 年に John Gruber が作成し、Aaron Swartz も大きく貢献した軽量マークアップ言語です。当初の目標はシンプルでありながら野心的なものでした。読みやすく書きやすいプレーンテキストで文章を書き、必要に応じて構造的に正しい HTML に変換できるようにすることです。

開始タグと終了タグが必要で読みづらくなりがちな HTML と違い、Markdown は直感的な記号で書式を表します。シャープ記号は見出しに、アスタリスクは太字や斜体に、ハイフンはリストになります。変換する前の状態でも、すっきりと読みやすい文書になるのが特徴です。

いまや Markdown は Web で文章を書くための事実上の標準です。GitHub の README、Reddit の投稿、数え切れないほどのソフトウェアのドキュメントで使われ、Notion、Obsidian、Slack などのツールもサポートしています。開発者やテクニカルライター、そしてオンラインで情報を発信するすべての人にとって、Markdown の理解はもはや必須といえます。

## Markdown の歴史

Markdown は、HTML の冗長さへの不満から生まれました。人気ブログ Daring Fireball を運営していた John Gruber は、プレーンテキストのように読みやすく、それでいてきれいな HTML を出力できる記法を求めていました。彼は Aaron Swartz とともに最初の仕様と、変換を行う Perl スクリプトを作りました。

2004 年以降、さまざまな拡張や派生が登場しました。GitHub Flavored Markdown（GFM）はタスクリスト、表、取り消し線などを追加しました。CommonMark は元の構文のあいまいさを解消するため、標準化された仕様を作ろうとしました。MultiMarkdown は脚注やメタデータなどで言語を拡張しました。

こうした違いはあるものの、中心となる構文はどの実装でも驚くほど安定していて一貫しています。

## 基本構文

### 見出し

Markdown の見出しにはシャープ記号（`#`）を使います。`#` の数が見出しのレベルを表します。

```markdown
# 見出し 1
## 見出し 2
### 見出し 3
#### 見出し 4
##### 見出し 5
###### 見出し 6
```

`#` ひとつがもっとも大きな見出し（HTML の `<h1>` に相当）、6 つでもっとも小さな見出し（`<h6>`）になります。ほとんどの文書では見出しレベル 1〜3 を使います。メインタイトルとして `# 見出し 1` は文書内でひとつだけにするのがベストプラクティスです。

### 太字と斜体

Markdown での強調はとても簡単です。アスタリスクかアンダースコア 1 つで囲むと斜体、2 つで囲むと太字になります。

```markdown
*斜体のテキスト* または _斜体のテキスト_
**太字のテキスト** または __太字のテキスト__
***太字かつ斜体*** または ___太字かつ斜体___
```

多くのスタイルガイドでは、一貫性のためにアンダースコアではなくアスタリスクを使うことを推奨しています。アンダースコアはファイル名や URL に含まれるアンダースコアと衝突することがあるからです。

### リスト

Markdown では番号付きリストと箇条書きリストの両方が使えます。箇条書きにはハイフン、アスタリスク、プラス記号を使います。

```markdown
- 1 つ目の項目
- 2 つ目の項目
  - ネストした項目
  - もうひとつのネストした項目
- 3 つ目の項目
```

番号付きリストは数字とピリオドで書きます。

```markdown
1. 最初のステップ
2. 次のステップ
3. 3 番目のステップ
   1. サブステップ
   2. もうひとつのサブステップ
```

面白いことに、番号付きリストで実際に書く数字は関係ありません。Markdown はどんな数字でも順番に表示します。ただし `1.` から順番に書いたほうが、元のテキストが読みやすくなります。

### リンクと画像

リンクは角かっこにテキスト、丸かっこに URL を書きます。

```markdown
[OpenAI を見る](https://openai.com)
[タイトル付きリンク](https://example.com "サンプルサイト")
```

画像も同じ書き方で、先頭に感嘆符を付けます。

```markdown
![画像の代替テキスト](https://example.com/photo.jpg)
![ロゴ](./images/logo.png "会社のロゴ")
```

同じ URL を何度も使うときは、参照スタイルのリンクを使うと本文をすっきり保てます。

```markdown
[Google][1] は検索エンジンです。[Bing][2] もそうです。

[1]: https://google.com
[2]: https://bing.com
```

### コード

インラインコードにはバッククォートを 1 つ使います。

```markdown
デバッグには `console.log()` 関数を使います。
```

コードブロックにはバッククォート 3 つ（フェンスドコードブロック）を使い、シンタックスハイライト用に言語名を指定することもできます。

````markdown
```javascript
function greet(name) {
  return `Hello, ${name}!`;
}
```
````

対応言語はレンダラーによって異なりますが、一般的に `javascript`、`python`、`html`、`css`、`bash`、`json`、`typescript` などが使えます。

### 引用

引用には不等号（>）を使います。

```markdown
> これは引用です。
> 複数行にわたって書けます。
>
> 複数の段落を含めることもできます。
```

引用はネストできます。

```markdown
> 1 段目
>> 2 段目
>>> 3 段目
```

### 表

表はパイプとハイフンで行と列を作ります。

```markdown
| 項目       | Markdown | HTML   |
|------------|----------|--------|
| 読みやすさ | 高い     | 低い   |
| 習得       | 簡単     | 普通   |
| 移植性     | 非常に高い | 高い |
```

区切り行にコロンを入れると、列の配置を指定できます。

```markdown
| 左寄せ   | 中央揃え | 右寄せ   |
|:---------|:--------:|---------:|
| テキスト | テキスト | テキスト |
```

### 水平線

1 行にハイフン、アスタリスク、アンダースコアを 3 つ以上並べると水平線になります。

```markdown
---
***
___
```

文書内のセクションを視覚的に区切るのに便利です。

## 応用機能

### タスクリスト

GitHub Flavored Markdown はタスクリストに対応しており、ToDo の管理にぴったりです。

```markdown
- [x] 導入を書く
- [x] コード例を追加する
- [ ] 記事を校正する
- [ ] 公開する
```

### 脚注

一部の Markdown 処理系は脚注に対応しています。

```markdown
ここに出典が必要な一文があります。[^1]

[^1]: これが脚注の内容です。
```

### 取り消し線

チルダ 2 つで取り消し線になります。

```markdown
~~このテキストは取り消されています。~~
```

### 定義リスト

一部の拡張 Markdown 実装は定義リストに対応しています。

```markdown
用語
: 用語の定義。

別の用語
: その定義。
```

## Markdown を使う理由

### 移植性

Markdown ファイルはプレーンテキストです。どの OS のどのテキストエディタでも開けます。独自形式に縛られることも、互換性の問題も、専用ソフトも必要ありません。

### バージョン管理との相性

Markdown はプレーンテキストなので、Git などのバージョン管理システムと非常に相性が良いです。変更履歴を追い、差分を確認し、プルリクエストで共同作業できます。`.docx` や `.pptx` のようなバイナリ形式ではほぼ不可能なことです。

### スピード

Markdown での執筆は速いです。構文を覚えてしまえば、手をキーボードから離す必要がありません。書式ボタンをクリックするためにマウスに手を伸ばすこともありません。そのため効率を重視する開発者やテクニカルライターに特に人気があります。

### 柔軟性

ひとつの Markdown ファイルを HTML、PDF、EPUB、DOCX、プレゼンテーションスライドなどに変換できます。Pandoc、printmd、各種静的サイトジェネレーターを使えば、こうした変換もスムーズです。一度書けば、どこにでも公開できます。

### 内容への集中

Markdown は書式の気を散らす要素を取り除きます。Markdown で書くときは、フォントサイズや色、余白ではなく、言葉と構成に集中できます。内容と見た目を分けることで、文章はより明快になります。

## はじめてみよう

Markdown を覚える一番の近道は、実際に使い始めることです。拡張子 `.md` の新しいファイルを作り、好きなテキストエディタで開いて書き始めましょう。プレビューツールを使えば、入力しながら表示結果を確認できます。

Markdown をプロ品質のレイアウトの PDF に変換したいなら、[printmd](https://printmd.app) のようなツールを使えば簡単です。内容を Markdown で書くだけで、組版やレイアウトはツールに任せられます。

手軽に練習したいなら、次のメモやプロジェクトの README、あるいはブログ記事を Markdown で書いてみてください。1 時間もすれば構文が自然に感じられ、なぜ今までほかのものを使っていたのか不思議に思うはずです。

## まとめ

Markdown は、現代の Web でもっとも重要な執筆ツールのひとつとしての地位を確立しました。シンプルさ、移植性、柔軟性を兼ね備え、ちょっとしたメモから本格的な技術ドキュメントまで幅広く使えます。API のドキュメントを書く開発者、講義ノートを取る学生、ブログ記事の下書きをするライター、誰にとっても Markdown はクリーンで効率的な土台になります。

このガイドで紹介した構文で、執筆のほとんどの場面に対応できます。慣れてきたら、脚注や定義リスト、数式表記などの拡張機能も試して、さらに可能性を広げてみてください。
