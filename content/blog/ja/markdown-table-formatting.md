## なぜ Markdown で表を使うのか？

表は、構造化されたデータを示すもっとも効果的な方法のひとつです。比較表、料金プラン、機能一覧、スケジュール、参照用のデータなどは、どれも表にすると見やすくなります。Markdown の表はシンプルさと実用性のバランスがよく、テキストエディタから離れることなく、すっきりと読みやすい表を作れます。

Markdown の表は HTML の表やスプレッドシートほど高機能ではありませんが、ドキュメント、ブログ記事、プロジェクトのレポートで書き手が出会う場面のほとんどに対応できます。構文、できること、制約を理解しておけば、どんな Markdown 文書でもデータをわかりやすく示せます。

## 表の基本構文

Markdown の表は、ヘッダー行、区切り行、データ行の 3 つの部分でできています。

```markdown
| 名前    | 役割         | 拠点       |
|---------|--------------|------------|
| Alice   | 開発者       | ニューヨーク |
| Bob     | デザイナー   | ロンドン   |
| Charlie | マネージャー | 東京       |
```

表示結果は次のとおりです。

| 名前    | 役割         | 拠点       |
|---------|--------------|------------|
| Alice   | 開発者       | ニューヨーク |
| Bob     | デザイナー   | ロンドン   |
| Charlie | マネージャー | 東京       |

パイプ（`|`）で列を区切ります。区切り行（ハイフン）でヘッダーと本体を分けます。ハイフンは 3 つ以上あれば、数はいくつでもかまいません。

### 最小限の書き方

ソースのテキストでパイプの位置をそろえる必要はありません。次の書き方でもまったく問題ありません。

```markdown
|名前|役割|拠点|
|---|---|---|
|Alice|開発者|ニューヨーク|
|Bob|デザイナー|ロンドン|
```

ただし、パイプの位置をそろえておくと、元の Markdown がずっと読みやすく、編集しやすくなります。ほとんどの Markdown エディタには、自動で位置をそろえる「表の整形」コマンドがあります。

### 先頭と末尾のパイプ

一部のパーサーでは、外側のパイプは厳密には省略できます。

```markdown
名前 | 役割 | 拠点
--- | --- | ---
Alice | 開発者 | ニューヨーク
```

それでも、外側のパイプは書いておくことをおすすめします。表の構造がはっきりし、どの Markdown 処理系でも互換性が保たれます。

## 列の配置

区切り行にコロンを入れると、列の中のテキストの配置を指定できます。

```markdown
| 左寄せ         | 中央揃え       | 右寄せ         |
|:---------------|:--------------:|---------------:|
| テキスト       |   テキスト     |       テキスト |
| 長めのテキスト | 長めのテキスト | 長めのテキスト |
```

- `:---` または `---` = 左寄せ（既定）
- `:---:` = 中央揃え
- `---:` = 右寄せ

数値データでは特に便利で、右寄せにすると読みやすくなります。

```markdown
| 品目        | 数量    | 単価  | 合計        |
|:------------|:-------:|------:|------------:|
| 部品 A      |   50    | $2.99 |     $149.50 |
| 部品 B      |  120    | $1.50 |     $180.00 |
| 部品 C      |   30    | $8.75 |     $262.50 |
| **合計**    | **200** |       | **$592.00** |
```

## 表の中の書式

### インラインの書式

表のセルの中では、標準的な Markdown のインライン書式を使えます。

```markdown
| 機能           | 状態          | メモ                       |
|:---------------|:-------------:|:---------------------------|
| 認証           | **完了**      | OAuth 2.0 を使用           |
| ダッシュボード | *進行中*      | `v2.1` で提供予定          |
| API v2         | ~~中止~~      | GraphQL に置き換え         |
| モバイルアプリ | `計画中`      | [ロードマップを見る](#roadmap) |
```

セルの中では太字、斜体、コード、取り消し線、リンクを使えます。ただし、セルの内容は簡潔にしましょう。複数の段落が必要なセルがあるなら、おそらく表は適した形式ではありません。

### 表の中のコード

インラインコードは表の中でもうまく機能します。

```markdown
| 関数             | 説明                     | 戻り値の型 |
|:-----------------|:-------------------------|:-----------|
| `getUser(id)`    | ID でユーザーを取得      | `User`     |
| `listUsers()`    | すべてのユーザーを一覧   | `User[]`   |
| `deleteUser(id)` | ID でユーザーを削除      | `boolean`  |
```

ただし、コードブロック（バッククォート 3 つ）は表のセルの中では使えません。複数行のコードを示したいときは、表の外に置いて参照するようにしましょう。

### 表の中の画像

小さな画像やアイコンなら、表のセルに入れられます。

```markdown
| プラットフォーム | アイコン                  | 状態     |
|:-----------------|:--------------------------|:---------|
| macOS            | ![mac](icons/mac.png)     | 対応     |
| Windows          | ![win](icons/windows.png) | 対応     |
| Linux            | ![linux](icons/linux.png) | ベータ版 |
```

画像は小さくしましょう。大きな画像は表のレイアウトを崩してしまいます。

## Markdown の表の制約

Markdown の表には、知っておくべき制約がいくつかあります。

### セルの結合ができない

セルを横にも縦にも結合できません。HTML の `colspan` や `rowspan` に相当するものはありません。データにセルの結合が必要なら、代わりに HTML の表を検討しましょう。

### セル内で改行できない

表の各行は、ソースでは 1 行で書かなければなりません。標準の Markdown 構文では、セルの中で改行できません。回避策はいくつかあります。

- `<br>` で改行する：`セルの 1 行目<br>セルの 2 行目`
- セルの内容を簡潔にし、詳しい内容は表の外に出す

### 表の入れ子ができない

標準の Markdown では、表の中に別の表を入れることはできません。

### キャプションがない

標準の Markdown の表はキャプションに対応していません。手動で追加できます。

```markdown
*表 1：地域別の四半期売上（単位：千ドル）*

| 地域         | Q1   | Q2   | Q3   | Q4   |
|:-------------|-----:|-----:|-----:|-----:|
| 北米         | $120 | $135 | $142 | $158 |
| ヨーロッパ   | $89  | $94  | $101 | $112 |
| アジア太平洋 | $67  | $73  | $81  | $95  |
```

### 幅を指定できない

Markdown には列の幅を指定する方法がありません。列の幅は内容によって決まります。正確に調整したいなら、HTML や CSS ベースのレンダリングツールを使う必要があります。

## 回避策と代替手段

### Markdown の中で HTML の表を使う

Markdown の表でできる範囲を超える機能が必要なときは、ほとんどの Markdown 処理系がインラインの HTML を受け付けます。

```html
<table>
  <tr>
    <th rowspan="2">名前</th>
    <th colspan="2">点数</th>
  </tr>
  <tr>
    <th>数学</th>
    <th>理科</th>
  </tr>
  <tr>
    <td>Alice</td>
    <td>95</td>
    <td>88</td>
  </tr>
</table>
```

セルの結合、スタイル、レイアウトを完全に制御できますが、Markdown の表の魅力である読みやすさは犠牲になります。

### 代わりに定義リストを使う

キーと値の組み合わせのデータなら、表より定義リストのほうが適しているかもしれません。

```markdown
プロジェクト名
: printmd

バージョン
: 2.1.0

ライセンス
: MIT

プラットフォーム
: クロスプラットフォーム（macOS、Windows、Linux）
```

### 外部ツールを使う

並べ替え、絞り込み、計算が必要な複雑なデータなら、スクリプトやスプレッドシートから Markdown の表を生成することを検討しましょう。データを Markdown の表として書き出せるツールはたくさんあります。

- **CSV から Markdown へ**：tableconvert.com などのオンライン変換ツール
- **Python**：`tabulate` などのライブラリでデータから Markdown の表を生成できる
- **VS Code 拡張機能**：「Markdown Table Prettify」や「Markdown Table Formatter」

## すっきりした表を作るコツ

### 書式を統一する

書式のスタイルを決めたら、文書全体でそれを守りましょう。配置、先頭と末尾のパイプを書くかどうか、空のセルをどう扱うかを決めておきます。

### シンプルに保つ

列が 7〜8 個を超えると、表は読みにくくなります。複数の表に分けるか、別の形式を使うことを検討しましょう。

### 表の生成ツールを使う

手作業で表を作るのが面倒になったら、表の生成ツールを使いましょう。表を視覚的に作って Markdown として書き出せる Web サイトやエディタの拡張機能がいくつもあります。

### PDF 出力での表

printmd のようなツールで Markdown 文書を PDF に変換するときは、表が特別に扱われます。printmd は次のようなよくある問題に対処します。

- ページをまたぐ表はきれいに分割され、ヘッダーが繰り返し表示される
- 列の幅が内容に応じて自動で計算される
- 罫線と余白が一貫して適用される
- Markdown のソースで指定した配置が保持される

つまり、標準的な Markdown で表を書くだけで、追加のスタイル設定なしにプロ品質の PDF に仕上がると安心できます。

## まとめ

Markdown の表は、ドキュメント、ブログ記事、技術文書で構造化されたデータを示すための実用的なツールです。HTML の表やスプレッドシートに比べると制約はありますが、ソースのままでもシンプルで読みやすいので、よくある用途のほとんどに最適です。

まずは基本をマスターしましょう。ヘッダー行、コロンによる配置、インラインの書式、統一されたスタイルです。制約も知っておきましょう。セルの結合ができない、セル内で改行できない、幅を指定できない、という点です。そうした制約にぶつかったら、HTML の表に切り替えるか、内容の構成を見直しましょう。

これらのテクニックを身につければ、どんな Markdown 文書でもデータをわかりやすく、プロらしく示せます。
