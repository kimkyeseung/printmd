## なぜ議事録に Markdown なのか？

議事録には重要な役割があります。決定事項、アクションアイテム、議論の内容を共有の記録として残すことです。よい議事録がなければ、会議は情報が入ったきり出てこないブラックホールになってしまいます。参加者はそれぞれ違う解釈で合意内容を持ち帰り、アクションアイテムは忘れられ、次の会議でまた同じ話をすることになります。

Markdown は議事録にぴったりの形式です。よくある問題をいくつも解決してくれるからです。

**スピード**：会議中に情報をすばやく書き留められます。Markdown の構文は最小限なので、キー入力を書式ではなく内容に使えます。ハイフンひとつで箇条書き、角かっこでチェックボックス。マウスをクリックする必要はありません。

**構造**：Markdown の見出しとリストを使えば、議事録に自然と構造が生まれます。文字がぎっしり詰まった文章ではなく、会議のあとに見返しやすい、整理されたセクションになります。

**検索性**：プレーンテキストのファイルは検索が簡単です。半年後に、ある決定がなされた会議を探す必要が出てきても、議事録のフォルダをテキスト検索すればすぐに見つかります。

**移植性**：Markdown ファイルはどこでも使えます。特定のソフトは不要で、サイズはごく小さく、何十年後でも読めます。サブスクリプションの期限が切れて、自分の会議の記録が見られなくなることもありません。

**バージョン管理**：チームで Git を使っているなら、議事録をプロジェクトと同じリポジトリに置けます。変更は追跡され、すべての履歴が残ります。

## 議事録のテンプレート

よいテンプレートがあれば、会議ごとの記録に一貫性が生まれ、必要な情報を漏れなく書き留められます。ほとんどのチームで使えるテンプレートを紹介します。

```markdown
---
title: "週次スタンドアップ - プロダクトチーム"
date: 2025-03-15
attendees:
  - Alice Chen
  - Bob Martinez
  - Carol Kim
  - David Park
absent:
  - Eve Johnson（休暇中）
---
```

## テンプレートの解説

### ヘッダー部分

ヘッダーには、誰が、いつ、どこで参加したかという基本的なメタデータを書きます。YAML フロントマターを使うと機械でも読み取れるので、将来議事録を解析するツールを作りたくなったときに役立ちます。

```markdown
---
title: "週次スタンドアップ - プロダクトチーム"
date: 2025-03-15
attendees:
  - Alice Chen
  - Bob Martinez
---
```

### アジェンダ

アジェンダは会議の前に書いておきましょう。参加者の心構えができ、議論が脱線しにくくなります。会議中は、すべてを時系列で書くのではなく、各アジェンダの下にメモを追加していけます。

### 議論のメモ

一言一句ではなく、要点を書き留めましょう。議事録は文字起こしではありません。次のようなことに集中します。

- 決定の判断材料になる発言
- 出された懸念や反対意見
- 共有されたデータや事実
- あとで重要になる背景情報

発言は具体的な人に結びつけて書きましょう。責任がはっきりし、フォローアップもしやすくなります。

### 決定事項

決定事項は議論と分けて書きます。決定事項専用のセクションがあれば、実際に何が決まり、何が話し合われただけなのかがすぐにわかります。決定事項に番号を振っておくと、あとのやり取りで参照しやすくなります。

### アクションアイテム

もっとも重要なセクションです。すべてのアクションアイテムには次の要素が必要です。

- **何を**：タスクの明確な説明
- **誰が**：担当者（グループではなく 1 人）
- **いつまでに**：具体的な期限

Markdown のチェックボックス（`- [ ]`）を使えば、完了状況を簡単に管理できます。

```markdown
- [x] **Alice**：ステージング環境を構築 - **期限：3 月 10 日**（完了）
- [ ] **Bob**：API ドキュメントを作成 - **期限：3 月 18 日**
```

## 議事録を整理する

### フォルダ構成

```
meetings/
  team-standup/
    2025-03-01.md
    2025-03-08.md
    2025-03-15.md
  one-on-ones/
    alice/
      2025-03-05.md
      2025-03-19.md
    bob/
      2025-03-07.md
      2025-03-21.md
  client/
    acme-corp/
      2025-03-15.md
    beta-inc/
      2025-03-12.md
  retrospectives/
    sprint-14.md
    sprint-15.md
```

### 命名規則

ファイル名の先頭には日付を付けましょう。`2025-03-15.md` や `2025-03-15-weekly-standup.md` のようにします。こうすると、ファイルが自動的に日付順に並び、日付での検索も簡単になります。

### 関連する議事録をリンクする

話題が次の会議に持ち越されるときは、議事録同士を相互参照しましょう。

```markdown
## [3 月 8 日のスタンドアップ](./2025-03-08.md)からの持ち越し

David の通貨バグはまだ未解決。
[最初の議論](./2025-03-08.md#blockers)を参照。
```

## 共有と保管

### 会議後の共有

議事録は会議の終了から 1 時間以内に送りましょう。時間が経つほど役に立たなくなります。よく使われる共有方法は次のとおりです。

1. **Git コミット**：共有リポジトリに議事録をプッシュします。チームメンバーには、いつもの Git の流れで通知が届きます。
2. **メール**：Git を使わない関係者には、議事録の PDF を添付した要約メールを送ります。printmd のようなツールを使えば、Markdown の議事録をすっきりした PDF に変換できます。
3. **Slack/Teams**：チームのチャンネルに要約を投稿し、議事録全文へのリンクを添えます。
4. **Confluence/Notion**：Wiki でドキュメントを管理したいチームもあります。Markdown で書いてから、これらのツールに貼り付けられます。

### 保管の方針

議事録の「賞味期限」はさまざまです。半年前のスタンドアップの記録が必要になることはまれですが、クライアントとの打ち合わせや決定の記録は何年もあとに参照されることがあります。

次のような保管方法を検討しましょう。

- **現行の議事録**：今四半期のもの。メインのフォルダに置いてすぐ見られるようにします。
- **アーカイブ**：古い議事録は `archive/` フォルダに移し、年ごとに整理します。
- **永久保存**：決定事項のログとクライアントとの打ち合わせの議事録は無期限で保管します。

## よりよい議事録のためのコツ

### 会議の前に

- アジェンダを書き込んだテンプレートを準備する。
- 前回の会議のアクションアイテムを見直す。
- 参加者が準備できるよう、アジェンダを共有しておく。

### 会議中に

- すべての発言ではなく、決定事項とアクションアイテムの記録に集中する。
- 略語や省略した書き方を使う。あとで清書すればよい。
- 責任を明確にするため、誰が何を言ったかを書き留める。
- フォローアップが必要な項目には、わかりやすい目印を付ける。

### 会議のあとに

- 議論の記憶が新しいうちに、1 時間以内に議事録を整える。
- アクションアイテムを担当者と確認する。
- すぐに議事録を共有する。
- 会議中に話に出たリンク、資料、参考情報を追加する。

### 文字起こしはしない

議事録は会議の文字起こしではありません。会話そのものではなく、中身を書き留めましょう。誰かが 5 分かけてある話題について話したとしても、議事録ではその要点をまとめた 2 文とアクションアイテム 1 つで十分かもしれません。

## Markdown の議事録と相性のよいツール

- **Obsidian**：議事録をプロジェクトのノートとリンクさせ、議論のナレッジグラフを作るのに最適。
- **VS Code**：Markdown プレビューと Git 連携ですばやく編集できる。
- **printmd**：書式の整った文書を好む関係者と共有するときに、議事録を PDF に変換できる。
- **Git**：議事録のバージョン管理。変更を追跡し、履歴を残せる。
- **grep/ripgrep**：コマンドラインから、すべての議事録を一瞬で検索できる。

## まとめ

Markdown の議事録は、速く書けて、検索しやすく、共有も簡単です。大切なのは一貫性です。同じテンプレートを使い、同じ命名規則に従い、毎回の会議のあとすぐに議事録を共有しましょう。

このガイドのテンプレートから始めて、チームのニーズに合わせて調整し、議事録を「あとで思い出してやること」ではなく習慣にしましょう。よい議事録に費やす 30 分が、のちのちの混乱や同じ議論の繰り返しに費やす何時間もの時間を節約してくれます。
