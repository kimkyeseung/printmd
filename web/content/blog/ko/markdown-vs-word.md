# 마크다운 vs 워드: 어떤 걸 써야 할까?

문서를 작성할 때 가장 먼저 결정해야 할 것은 어떤 도구를 사용할 것인가입니다. 가장 대중적인 도구인 Microsoft Word와 개발자를 중심으로 확산되고 있는 마크다운, 두 도구의 특성을 비교해보고 어떤 상황에서 어떤 도구가 적합한지 알아보겠습니다.

## 한눈에 보는 비교

| 항목 | 마크다운 | Microsoft Word |
|:-----|:--------:|:--------------:|
| 학습 난이도 | 쉬움 | 보통 |
| 파일 크기 | 매우 작음 | 큼 |
| 버전 관리 | 우수 (Git 호환) | 제한적 |
| 협업 | Git 기반 | 실시간 공동 편집 |
| 서식 자유도 | 제한적 | 매우 높음 |
| 플랫폼 지원 | 모든 플랫폼 | Windows/Mac |
| 비용 | 무료 | 유료 |
| 호환성 | 순수 텍스트 | .docx 형식 |
| 인쇄/레이아웃 | 도구 필요 | 바로 가능 |
| 수학 공식 | LaTeX 지원 | 내장 수식 편집기 |

## 마크다운의 장점

### 1. 어디서든 열 수 있다

마크다운 파일은 순수 텍스트이므로 메모장부터 VS Code까지 어떤 텍스트 편집기에서든 열 수 있습니다. 10년 후에도 문제없이 읽을 수 있다는 것은 큰 장점입니다.

```
# 마크다운 파일은 이렇게 생겼습니다
- 어떤 에디터에서든 열 수 있습니다
- 별도의 프로그램이 필요 없습니다
- **서식 정보**도 텍스트로 표현됩니다
```

반면 Word 파일(.docx)은 Microsoft Word나 호환 프로그램이 있어야 정상적으로 열립니다. 호환 프로그램에서 열면 레이아웃이 깨지는 경우도 흔합니다.

### 2. 버전 관리가 쉽다

마크다운은 텍스트 기반이므로 Git으로 완벽하게 버전 관리가 가능합니다.

```bash
# 변경 내용을 한눈에 확인
git diff document.md

# 변경 사항:
# - 기존: 서버 응답 시간은 평균 200ms입니다.
# + 변경: 서버 응답 시간은 평균 150ms로 개선되었습니다.
```

Word 파일은 바이너리 형식이므로 Git으로 diff를 확인할 수 없습니다. 변경 이력 추적은 Word의 내장 기능에 의존해야 합니다.

### 3. 파일 크기가 작다

1,000단어 분량의 문서를 비교하면 차이가 뚜렷합니다.

| 형식 | 파일 크기 |
|------|--------:|
| .md (마크다운) | ~5 KB |
| .docx (Word) | ~30 KB |
| .docx (이미지 포함) | ~500 KB 이상 |

마크다운 파일은 이메일 첨부, 메신저 전송, 클라우드 저장 등 어디에서든 부담 없이 공유할 수 있습니다.

### 4. 내용에 집중할 수 있다

마크다운에서는 서식을 고르느라 시간을 낭비하지 않습니다. 폰트를 바꾸거나 색상을 고를 필요 없이, 구조와 내용에 집중할 수 있습니다. 최종 스타일은 변환 단계에서 일괄 적용하면 됩니다.

### 5. 자동화와 통합이 쉽다

마크다운은 텍스트 기반이므로 스크립트로 처리하기 쉽습니다.

```bash
# 모든 마크다운 파일에서 특정 텍스트 치환
sed -i 's/old-url.com/new-url.com/g' docs/*.md

# 여러 파일을 하나의 PDF로 합치기
cat intro.md chapter1.md chapter2.md | md-to-pdf
```

CI/CD 파이프라인에서 문서를 자동으로 빌드하고 배포하는 것도 가능합니다.

## Word의 장점

### 1. 실시간 공동 편집

Microsoft 365의 실시간 공동 편집 기능은 마크다운으로는 따라하기 어렵습니다. 여러 사람이 동시에 같은 문서를 편집하면서 변경 사항을 즉시 확인할 수 있습니다.

### 2. 풍부한 서식 옵션

Word는 글꼴, 색상, 크기, 간격, 머리글/바닥글, 목차 자동 생성, 페이지 번호 등 세밀한 서식 설정이 가능합니다. 마크다운은 이런 부분에서 제한적입니다.

### 3. 비개발자와의 협업

마크다운 문법을 모르는 사람에게는 Word가 더 편합니다. 특히 경영진, 마케팅, 영업 등 비개발 직군과 협업할 때는 Word가 현실적인 선택입니다.

### 4. 검토 및 주석 기능

Word의 변경 내용 추적과 주석 기능은 문서 검토 워크플로우에 최적화되어 있습니다. 마크다운에서는 PR 리뷰로 대체할 수 있지만, 비개발자에게는 익숙하지 않습니다.

### 5. 복잡한 레이아웃

다단 편집, 텍스트 상자, 도형 삽입, 워터마크 등 복잡한 레이아웃이 필요한 문서에는 Word가 적합합니다.

## 상황별 추천

### 마크다운이 적합한 경우

- **기술 문서**: API 문서, 개발 가이드, README
- **블로그 포스트**: 특히 기술 블로그
- **개인 메모/노트**: 빠른 기록과 정리
- **버전 관리가 필요한 문서**: 정책 문서, 규격 문서
- **개발팀 내부 문서**: 위키, 온보딩 가이드
- **이력서**: 코드처럼 관리하는 이력서 (printmd로 PDF 변환)

### Word가 적합한 경우

- **공식 비즈니스 문서**: 계약서, 제안서, 견적서
- **비개발자와의 협업**: 마케팅 자료, 기획 문서
- **복잡한 레이아웃**: 보고서, 매뉴얼, 소책자
- **학술 논문**: 저널 투고 양식이 Word를 요구하는 경우
- **서식이 중요한 문서**: 정부 제출 문서, 법률 문서

### 둘 다 사용하는 하이브리드 접근

실무에서는 하나만 고집하기보다 상황에 따라 적절히 혼용하는 것이 좋습니다.

1. **초안은 마크다운으로**: 빠르게 내용을 작성합니다.
2. **검토는 상황에 따라**: 개발팀이면 PR 리뷰, 비개발팀이면 Word 변환 후 검토합니다.
3. **최종본은 필요에 따라**: 웹 배포면 마크다운, 인쇄면 PDF, 공유면 Word로 변환합니다.

## 마크다운에서 Word로, Word에서 마크다운으로

### 마크다운 -> Word

Pandoc을 사용하면 마크다운을 Word 파일로 변환할 수 있습니다.

```bash
pandoc document.md -o document.docx
```

스타일 템플릿을 지정하면 더 깔끔한 결과를 얻을 수 있습니다.

```bash
pandoc document.md -o document.docx --reference-doc=template.docx
```

### Word -> 마크다운

```bash
pandoc document.docx -o document.md
```

다만 Word의 복잡한 서식은 마크다운으로 완벽히 변환되지 않을 수 있습니다. 변환 후 수동 정리가 필요할 수 있습니다.

### 마크다운 -> PDF

마크다운을 PDF로 변환하면 Word 못지않게 깔끔한 문서를 만들 수 있습니다. printmd를 사용하면 별도의 설정 없이 한글 문서도 깔끔하게 PDF로 변환됩니다.

## 생산성 비교

실제 작업 속도를 비교해보겠습니다.

### 문서 작성 속도

| 작업 | 마크다운 | Word |
|------|---------|------|
| 제목 추가 | `## 제목` (1초) | 텍스트 입력 -> 스타일 선택 (3초) |
| 굵은 글씨 | `**텍스트**` (1초) | 텍스트 선택 -> Ctrl+B (2초) |
| 코드 삽입 | 백틱 3개 (1초) | 서식 변경 여러 단계 (10초) |
| 목록 작성 | `- 항목` (즉시) | 자동 목록 (비슷) |
| 표 작성 | 파이프 문법 (보통) | GUI로 삽입 (쉬움) |

키보드에서 손을 떼지 않고 작업할 수 있다는 점에서 마크다운이 전반적으로 빠릅니다. 하지만 표 작성이나 이미지 배치 같은 작업은 Word의 GUI가 더 직관적입니다.

### 파일 관리 효율

```
# 마크다운: 폴더 기반으로 깔끔하게 정리
docs/
├── api/
│   ├── authentication.md
│   └── endpoints.md
└── guides/
    ├── getting-started.md
    └── deployment.md

# Word: 파일 이름으로만 구분
문서/
├── API_인증_가이드_v3_최종_진짜최종.docx
├── API_엔드포인트_수정본.docx
└── 시작하기_김대리수정_0220.docx
```

이 차이는 프로젝트가 커질수록 더 두드러집니다.

## 마무리

마크다운과 Word는 경쟁 관계가 아니라 보완 관계입니다. 각각의 강점이 있고, 최적의 사용 시나리오가 다릅니다. 개발 관련 문서에는 마크다운이, 비즈니스 커뮤니케이션에는 Word가 더 적합합니다.

중요한 것은 도구에 얽매이지 않는 것입니다. 내용이 좋으면 어떤 형식이든 가치가 있습니다. 다만 효율적인 도구를 선택하면 같은 시간에 더 좋은 결과물을 만들 수 있습니다. 마크다운이 익숙해지면 printmd 같은 도구를 활용해 PDF나 인쇄 가능한 형태로 쉽게 변환할 수 있으니, 마크다운을 아직 사용해보지 않았다면 한 번 도전해보시기 바랍니다.
