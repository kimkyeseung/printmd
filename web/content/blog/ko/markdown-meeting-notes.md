# 마크다운으로 회의록 작성하기

회의는 많이 하지만, 회의록을 제대로 쓰는 팀은 드뭅니다. 회의가 끝나면 "아까 그거 뭐라고 했지?"하는 상황이 반복됩니다. 체계적인 회의록은 이런 문제를 해결해줍니다. 마크다운은 빠르게 작성할 수 있고, 구조화하기 쉬우며, 검색이 용이해서 회의록 작성에 안성맞춤입니다.

## 왜 마크다운으로 회의록을 쓸까?

### 빠르게 작성할 수 있다

회의 중에 실시간으로 기록해야 하므로 속도가 중요합니다. 마크다운은 키보드에서 손을 떼지 않고 서식을 적용할 수 있어 Word보다 빠릅니다.

```markdown
## 논의 사항

### 1. 신규 기능 일정
- 디자인 완료: 3/15까지 → **김디자이너** 담당
- 개발 시작: 3/18 → 프론트엔드 2명, 백엔드 1명
- QA: 4/1 ~ 4/5

### 2. 버그 수정 우선순위
- [x] 로그인 오류 (긴급)
- [ ] 검색 필터 초기화 안됨
- [ ] 모바일 레이아웃 깨짐
```

이 정도면 30초 안에 작성할 수 있습니다. Word에서 같은 내용을 서식 맞추면 2-3분은 걸립니다.

### 검색이 쉽다

마크다운은 순수 텍스트이므로 파일 내 검색이 완벽하게 동작합니다.

```bash
# "배포"라는 키워드가 포함된 회의록 찾기
grep -r "배포" meetings/

# 특정 날짜 범위의 회의록
ls meetings/2025-03-*.md
```

### 버전 관리가 된다

Git으로 관리하면 회의록의 수정 이력을 추적할 수 있습니다. 누가 언제 수정했는지, 무엇이 바뀌었는지 모두 기록됩니다.

### 다양한 형식으로 변환 가능

마크다운 회의록은 필요에 따라 PDF, HTML, Word 등으로 변환할 수 있습니다. 경영진에게 보고할 때는 printmd로 PDF로 변환하면 깔끔한 보고서 형태가 됩니다.

## 회의록 템플릿

### 기본 템플릿

```markdown
# [프로젝트명] 주간 회의

- **일시**: 2025-03-15 (월) 14:00-15:00
- **장소**: 3층 회의실 A / Zoom
- **참석자**: 김팀장, 이개발, 박디자인, 최기획
- **작성자**: 이개발

---

## 지난 회의 액션 아이템 확인

- [x] @이개발 - API 문서 업데이트 → 완료
- [ ] @박디자인 - 메인 페이지 목업 → 진행중 (3/18 완료 예정)
- [x] @최기획 - 요구사항 정리 → 완료

---

## 논의 사항

### 1. 안건 제목

**배경**: 왜 이 안건을 논의하는지

**논의 내용**:
- 의견 1 (김팀장): ...
- 의견 2 (이개발): ...

**결정 사항**: 최종 결정된 내용

---

### 2. 안건 제목

...

---

## 액션 아이템

| 담당자 | 내용 | 기한 |
|--------|------|------|
| @이개발 | 로그인 버그 수정 | 3/17 |
| @박디자인 | 메인 페이지 목업 완성 | 3/18 |
| @최기획 | 사용자 인터뷰 일정 잡기 | 3/19 |

---

## 다음 회의

- **일시**: 2025-03-22 (월) 14:00
- **안건**: TBD
```

### 스프린트 회고 템플릿

```markdown
# 스프린트 #12 회고

- **일시**: 2025-03-15 (금) 16:00-17:00
- **참석자**: 개발팀 전원

## 스프린트 요약

| 항목 | 수치 |
|------|------|
| 완료 스토리 | 8/10 |
| 완료 포인트 | 34/40 |
| 버그 수정 | 5건 |
| 배포 횟수 | 3회 |

## Keep (계속할 것)

- 매일 15분 스탠드업 미팅이 소통에 도움이 됐다
- 코드 리뷰가 버그를 사전에 잡아냈다
- 페어 프로그래밍이 효과적이었다

## Problem (문제점)

- QA 시간이 부족해서 마지막에 급하게 진행했다
- 기획 변경이 스프린트 중간에 들어와서 일정이 밀렸다
- 기술 부채가 점점 쌓이고 있다

## Try (시도할 것)

- [ ] QA 일정을 스프린트 계획에 명시적으로 포함
- [ ] 스프린트 중간 기획 변경은 다음 스프린트로 이월
- [ ] 매 스프린트에 기술 부채 해소 스토리 1개 포함
```

### 1:1 미팅 템플릿

```markdown
# 1:1 미팅 - 김팀장 & 이개발

- **일시**: 2025-03-15

## 근황

- 현재 진행 중인 업무: 결제 모듈 리팩토링
- 컨디션/워크로드: 적정

## 논의 사항

### 커리어 발전
- 프론트엔드 아키텍처에 관심이 있음
- 사내 스터디 참여 의향

### 업무 관련
- 결제 모듈 복잡도가 높아서 예상보다 시간이 걸림
- 테스트 커버리지 목표치 논의 필요

## 피드백

- 지난 PR 리뷰 퀄리티가 많이 좋아짐 (팀장)
- 코드 컨벤션 문서 정리해주셔서 팀에 도움이 됨 (팀장)

## 액션 아이템

- [ ] @이개발 - 아키텍처 관련 세미나 조사 (다음 1:1까지)
- [ ] @김팀장 - 테스트 커버리지 가이드라인 정리
```

## 액션 아이템 추적

회의의 핵심은 결정과 액션 아이템입니다. 마크다운의 체크리스트로 깔끔하게 추적할 수 있습니다.

### 체크리스트 활용

```markdown
## 이번 주 액션 아이템

### 긴급

- [x] @이개발 - 결제 오류 핫픽스 (3/15)
- [ ] @박디자인 - 에러 페이지 디자인 (3/16)

### 일반

- [ ] @이개발 - API v2 문서 업데이트 (3/19)
- [ ] @최기획 - 사용자 설문 결과 정리 (3/20)
- [ ] @김팀장 - 다음 분기 로드맵 초안 (3/22)
```

### 담당자별 정리

```markdown
## 담당자별 액션 아이템

### @이개발
| 내용 | 기한 | 상태 |
|------|------|------|
| 결제 오류 핫픽스 | 3/15 | 완료 |
| API v2 문서 업데이트 | 3/19 | 진행중 |
| 로그인 모듈 리팩토링 | 3/25 | 대기 |

### @박디자인
| 내용 | 기한 | 상태 |
|------|------|------|
| 에러 페이지 디자인 | 3/16 | 진행중 |
| 모바일 반응형 점검 | 3/20 | 대기 |
```

### 파일명 규칙

`YYYY-MM-DD-회의유형.md` 형식으로 통일하면 정렬과 검색이 편합니다.

## 공유와 보관

### Git으로 관리

```bash
# 회의록 커밋
git add meetings/2025/03/2025-03-15-주간회의.md
git commit -m "docs: 3/15 주간 회의록 추가"
git push
```

### Slack/Teams 공유

회의록을 Git에 푸시한 후 링크를 팀 채널에 공유합니다.

```
📋 3/15 주간 회의록이 업로드되었습니다.
https://github.com/team/repo/blob/main/meetings/2025/03/2025-03-15-주간회의.md

주요 결정사항:
- 신규 기능 개발 3/18 시작
- QA 일정 1주 → 2주로 확대
```

### PDF로 보관

중요한 회의록이나 공식 보고용 회의록은 PDF로 변환하여 보관합니다. printmd를 사용하면 마크다운 회의록을 깔끔한 PDF로 바로 변환할 수 있습니다. 특히 경영진에게 보고할 때나 프로젝트 산출물로 제출할 때 유용합니다.

## 실전 작성 팁

### 1. 회의 전에 템플릿을 준비하라

회의 시작 전에 템플릿에 참석자, 안건 등 기본 정보를 미리 채워두세요.

### 2. 실시간으로 기록하라

회의 후에 기억에 의존해서 작성하면 빠지는 내용이 많습니다. 회의 중에 바로 기록하세요. 키워드만 빠르게 적어두고, 회의 후에 정리해도 됩니다.

### 3. 결정 사항을 명확히 표시하라

```markdown
> **결정**: 배포 일정을 3/25에서 4/1로 변경한다.
> **이유**: QA 기간을 충분히 확보하기 위해
```

### 4. 액션 아이템에 담당자와 기한을 꼭 넣어라

담당자나 기한이 없는 액션 아이템은 실행되지 않습니다.

```markdown
<!-- 나쁜 예 -->
- [ ] API 문서 업데이트

<!-- 좋은 예 -->
- [ ] @이개발 - API v2 문서에 인증 섹션 추가 (3/19까지)
```

### 5. 불필요한 내용은 과감히 생략하라

모든 발언을 속기할 필요는 없습니다. 결정, 액션 아이템, 핵심 논점만 기록하세요.

### 6. 회의 후 24시간 이내에 공유하라

회의록은 빨리 공유해야 가치가 있습니다. 회의 직후 또는 당일 중으로 공유하세요.

## 마무리

좋은 회의록은 좋은 회의의 시작입니다. 마크다운으로 회의록을 작성하면 빠르고 체계적으로 기록할 수 있으며, 검색과 공유도 쉬워집니다. 처음에는 간단한 템플릿부터 시작하고, 팀의 필요에 맞게 점진적으로 개선해나가세요.

중요한 것은 형식이 아니라 꾸준함입니다. 완벽하지 않아도 괜찮습니다. 매 회의마다 기록하는 습관을 들이는 것이 가장 중요합니다.
